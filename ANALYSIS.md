> Generated from a full read-only review of the repository.
> No files were modified during analysis. No secret values from `.env` are included — only variable names.

## Overview

This is an **early-stage Next.js 16 storefront** ("ModernStore") with PostgreSQL + Prisma 7 and Better Auth. Roughly **2,170 lines of hand-written TS/TSX across 26 source files**.

The honest summary: **the presentation layer is well-built, but the commerce layer doesn't exist yet.** Catalog browsing and authentication work end-to-end. Cart, orders, and checkout are database schema only — the UI pretends they work.

Git state also matters here: `git status` shows `app/api/products/`, `app/api/cart/`, and `app/test/` are **untracked** (never committed), and `app/api/route.ts` was deleted.

## 3. How the Application Works

### Rendering flow

```
Browser request
    │
    ▼
proxy.ts  ──── checks for a session cookie on /dashboard, /sign-in, /sign-up
    │           (cookie PRESENCE only — no cryptographic/DB verification)
    ▼
app/layout.tsx  ─── renders Navbar + Footer around the page
    │
    ▼
Page component
    ├── Server Component (homepage, /products, /products/[id])
    │      └── calls prisma.* directly → PostgreSQL
    │      └── returns HTML + data, no client JS needed for the data
    │
    └── Client Component (Navbar, ProductFilters, auth cards)
           └── hydrates in browser, makes fetch() calls
```

**Two data paths exist side by side:**

1. **Server Component path (primary, correct):** `app/page.tsx:17` and `app/products/page.tsx:53` query Prisma directly inside the server component. Data arrives pre-rendered — fast, SEO-friendly, no client waterfall.

2. **Client fetch path (secondary):** `app/test/page.tsx:31` calls `fetch("/api/products")` from the browser → `app/api/products/route.ts:6` runs `prisma.product.findMany()`. This path is only used by the debug page.

### Authentication flow

```
Sign-up form (client)
  → authClient.signUp.email()                    lib/auth-client.ts
  → POST /api/auth/[...all]/sign-up/email        app/api/auth/[...all]/route.ts
  → toNextJsHandler(auth)                        lib/auth.ts
  → prismaAdapter(prisma)                        → PostgreSQL "user"/"account" tables
  → session cookie set
  → router.push("/dashboard")
```

On page load, `Navbar` calls `authClient.useSession()` (a React hook) to render sign-in buttons vs. a user dropdown.

### Route protection

`proxy.ts:29-38`:

- Signed-in user hits `/sign-in` or `/sign-up` → redirect to `/dashboard`
- Anonymous user hits `/dashboard` → redirect to `/sign-in?callbackUrl=...`
- The `config.matcher` at `proxy.ts:50` limits execution to exactly those 4 paths, so static assets aren't blocked.

### Query building (catalog)

`app/products/page.tsx:25-49` builds a `Prisma.ProductWhereInput` from URL search params:

- `?category=` → case-insensitive equality
- `?q=` → `OR` over name/description, case-insensitive `contains`
- `?sort=` → `orderBy` on `price` or `createdAt`

Two queries run in parallel via `Promise.all` at line 52: filtered products + distinct categories for the filter pills.

## 5. Code Quality, Bugs, Security

### 🔴 Build is broken

**`npx tsc --noEmit` fails:**

```
app/api/cart/route.ts' is not a module.
app/api/products/[id]/route.ts' is not a module.
```

Both files are empty (0 bytes). Next's route validator requires every route file to export handlers. **This blocks a production build.**

**`npm run lint` fails:** 1 error, 3 warnings.

- `app/test/page.tsx:52` — **error**: `react-hooks/set-state-in-effect` (calls `fetchProducts()` synchronously in `useEffect`)
- `app/api/products/route.ts:4,14` — unused `request` and `error` params
- `app/test/page.tsx:17` — unused `ProductCardProps`

### 🔴 Security issues

1. **Route protection is bypassable** — `proxy.ts:16-18` uses `getSessionCookie(request)`, which only checks *whether a cookie named `session` exists*. It does not validate the token against the database. Sending `Cookie: session=anything` grants access to `/dashboard`. Worse, `app/dashboard/page.tsx` does **no server-side session check either** — so there's no second line of defense. Fix: call `auth.api.getSession({ headers })` in the dashboard server component.

2. **No security headers** — `next.config.ts` has no `headers()` for CSP, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, HSTS.

3. **Auth hardening not configured** — `lib/auth.ts` has no explicit `secret`, `baseURL`, `trustedOrigins`, rate limiting, email verification, or password reset. It relies entirely on defaults + env vars.

4. **Debug logging in production path** — `proxy.ts:15` runs `console.log(pathname)` on every matched request (noisy, leaks navigation patterns to logs).

5. **Silent failures** — `app/api/products/route.ts:14-18` catches errors and returns 500 **without logging the error**. You'd never know why it failed.

6. **Unbounded public endpoint** — `GET /api/products` returns the entire table with no pagination, no auth, no rate limit. Fine at 13 products; a DoS vector at scale.

### 🟡 Bugs

1. **Geist fonts are loaded but never applied.** `app/layout.tsx:7-15` defines `--font-geist-sans`, but `app/globals.css:23` sets `body { font-family: Arial, Helvetica, sans-serif; }` and the `<body>` has no `font-sans` class. **Users see Arial.** Two font files downloaded for nothing.

2. **Nested `<main>` elements (invalid HTML).** `app/sign-up/page.tsx:56` renders `<main>`, but the root layout already wraps children in `<main>` (`app/layout.tsx:34`). `<main>` must not be nested.

3. **Dead code:** `components/auth/SignUpCard.tsx` (150 lines) — never imported.

4. **Duplicate, diverging auth implementations.** `app/sign-up/page.tsx` reimplements sign-up with *different* validation (min 8 chars, confirm password, show/hide eye toggles) than `SignUpCard.tsx`. `app/sign-in` uses the Card; `app/sign-up` doesn't. One of them will drift.

5. **`next/image` will crash on non-Unsplash images.** `next.config.ts:5-10` allows only `images.unsplash.com`. Seed data is all Unsplash so it works today — any admin-added product with another image host throws a runtime error.

6. **Debug page shipped to production** — `app/test/page.tsx` is a leftover with a lint error, reachable at `/test`.

7. **Duplicate DB query on product pages** — `generateMetadata` (line 21) and the page component (line 42) each call `prisma.product.findUnique` for the same ID.

8. **No error/loading boundaries** — zero `loading.tsx`, `error.tsx`, or `not-found.tsx` anywhere. A DB outage on the homepage = raw unhandled error page.

### 🟡 Bad practices

1. **`Float` for money** — `schema.prisma:88` (`price Float`) and `:120` (`total Float`). Floating-point arithmetic on currency causes rounding errors (`0.1 + 0.2 !== 0.3`). Use `Decimal` (Prisma) or integer cents.

2. **No pagination** — `app/products/page.tsx:53` fetches *every* product on every request.

3. **Hand-written type duplicating the ORM model** — `ProductCard.tsx:5-13` defines `ProductType` manually; `app/test/page.tsx:7-15` defines it *again*. Both can silently drift from `prisma/schema.prisma`. Use `Prisma.ProductGetPayload<{ select: ... }>` or the generated model type.

4. **No DB indexes for query patterns** — `Product.category` and the search fields are queried with `ILIKE '%q%'` but have no index. `Order.userId` has no index. (Acceptable at current scale.)

5. **Missing `postinstall`/`prisma generate` step** — `generated/prisma/` is gitignored but no script regenerates it. A fresh clone + `npm install && npm run build` **fails**.

6. **Misleading migration names** — the two migration names are inverted.

7. **Empty artifacts** — `validation/` (empty dir), `public/*.svg` (unused defaults), `tsconfig.tsbuildinfo` (0 bytes).

8. **README is untouched `create-next-app` boilerplate** with `# shoping-website` (typo) appended. No setup, env, or seed instructions.

9. **Uncommitted work** — API routes and the test page are untracked; `proxy.ts` has staged *and* unstaged changes.

### ✅ What's done well

- **Correct Prisma 7 usage** — driver adapter (`@prisma/adapter-pg`), `prisma-client` generator with explicit output, `prisma7.config.ts`.
- **Correct Next.js 16 usage** — `proxy.ts` (not the deprecated `middleware.ts`), `await searchParams` / `await params` (async request APIs).
- **Server Component data fetching** instead of client-side waterfall — the right default.
- **`Promise.all`** for parallel queries (`products/page.tsx:52`).
- **Proper error handling in auth forms** — `onRequest`/`onSuccess`/`onError` with loading states and `role="alert"`.
- **Prisma singleton pattern** correctly implemented (`lib/prisma.ts`).
- **`.env` properly gitignored**, secrets not in history.
- **`Promise`-typed `params`/`searchParams`** interfaces — matches Next 16 conventions.
- **Idempotent seed script.**
- **Strong, consistent visual design** with good accessibility fundamentals.
